Vector engine

vtracer-wasm 0.1.0, by jsscheller, exposes the VisionCortex tracing pipeline as a browser WebAssembly module. The bundled version uses VisionCortex 0.8.1. It is not the newer VTracer 1.0 alpha package. The JavaScript loader and WASM file are bundled locally.

SVG cleanup

SVGO 4.0.0 is bundled as a browser module, under the MIT licence. Dependency notices are included in js/vendor/licenses/. Multipass optimisation reduces coordinate precision, simplifies path data and removes redundant markup. If optimisation would increase bytes, the smaller original vector markup is kept.

Local preprocessing

Original JavaScript for Jenga-Code reduces the source to a bounded palette using a weighted median-cut method over a 5-bit-per-channel colour histogram. Palette lookup is cached by colour bin. Result fills are snapped to that palette so colour count remains bounded. This loses colour detail deliberately; it is not lossless reconstruction.

Speckle area controls the tracing engine’s minimum region size in working-image pixels. Curve simplification is its segment-length threshold. Corner threshold controls corner detection; it is not a promise to preserve every corner. Pixel mode follows pixel boundaries and can produce larger SVGs.

For colour and pixel modes, alpha below 50% is transparent when preservation is selected; semi-transparent pixels are composited onto white. A transparent border activates the engine’s alpha keying and is cropped out using the SVG viewBox. Black-and-white mode traces dark regions only, with white left transparent.

Honest measurements

SVG size is the actual UTF-8 size of the downloaded markup. Paths counts the final SVG path elements; SVGO may merge paths or convert shapes. Colours counts distinct traced fills before equivalent colour syntax is compressed. Time covers preprocessing, tracing and optimisation inside the worker, excluding image decoding and the initial WASM download. A more detailed trace can be larger than its source raster.
